## TCPServer

이 프로젝트는 다중 클라이언트 접속과 분산 서버 환경을 테스트하기 위해 구축된 C# 기반의 커스텀 TCP 기반 서버/클라이언트입니다. 기초적인 MMORPG의 시스템을 구현하고 여러 아키텍처를 실험하는 것을 목적으로 개발되었습니다.

## 사용된 언어 및 핵심 기술

* **언어**: C#
* **네트워크 통신**: 순수 TCP 소켓 기반의 IOCP (SocketAsyncEventArgs) 비동기 통신 엔진 자체 구축
  * `BufferManager`를 통한 메모리(Byte Array) 사전 할당 및 조각 임대(Slicing)로 C#의 Garbage Collection(GC) 렉(Pause) 원천 차단
  * 각각 1,000개 규모의 `SAEA(Recv/Send)` 풀링 시스템 설계
* **패킷 직렬화**: **Google Protobuf (Protocol Buffers)**

## 🏗 서버 아키텍처

로비와 게임 서버를 물리적으로 쪼개어 부하를 분산시킬 수 있게 설계되었습니다.
1. **AuthServer (인증 서버)**
   * 유저의 로그인, 회원가입 등을 전담합니다. 
   * 향후 분리가 완벽해지면 AuthDB와의 독립적 통신을 통해 로그인 트래픽과 인게임 트래픽을 분리합니다.
2. **GameServer (게임 서버)**
   * 유저의 실제 이동, 채팅, 전투 등의 부하가 큰 연산을 담당합니다.
   * 내부적으로 다수의 인스턴스(채널)를 분리하여 동기화 부하를 억제합니다.

## 🚀 적용된 주요 게임 시스템

### 1. 다중 캐릭터 / DB 세션 연동 시스템
* 계정(Account) 하나에 여러 명의 게임 캐릭터를 생성할 수 있습니다.
* 데이터베이스(현재는 로컬 캐시 메모리)에 캐릭터 데이터를 저장하고 불러와 로그인 후 "캐릭터 선택 창"을 거친 뒤 게임에 진입합니다.

### 2. 채널(인스턴스) 시스템
* 하나의 맵에 너무 많은 유저 패킷이 겹치지 않게 하기 위해 **채널 매니저**가 존재합니다.
* 유저는 1번부터 5번 채널까지 자유롭게 이동 가능하며, "같은 채널" 내에 있는 플레이어와 몬스터 객체끼리만 브로드캐스트 패킷을 공유합니다.

### 3. 위치 동기화 및 3D 좌표 스펙
* 모든 플레이어와 객체(몬스터)는 `X, Y, Z` 부동소수점 좌표값을 가집니다.
* 움직임이 발생할 때마다 델타 좌표만이 아닌 실제 위치 값(`S2C_MoveSync`)이 백엔드에서 주변 유저에게 뿌려져 화면에 동기화됩니다.

### 4. 실시간 채팅
* **로컬 챗(일반 채팅)**: 내가 속한 채널의 근처 유저들에게만 들리는 채팅
* **글로벌 챗(확성기)**: 서버 전체 채널에 브로드캐스팅 되는 전역 채팅을 라디오버튼으로 구분해 구현했습니다.

### 5. 거리 기반 타겟팅 전투 시스템 (Combat System)
* 공격 범위에 대한 서버(Autority) 검증
  * 단순히 "공격했다"고 데미지가 들어가는 것이 아니라, 패킷을 받으면 서버가 플레이어의 좌표와 타겟 몬스터의 좌표를 유클리디안 거리(`Math.Sqrt`)로 연산합니다.
  * 서버에서 정해둔 사거리(4.0f) 바깥의 타겟을 공격 시 타격을 무시하여 해킹(Range Hack)을 1차적으로 방어합니다.
* 패킷 기반 데미지 및 사망 판정 동기화(`S2C_AttackSync`).

### 6. 몬스터 자율형 AI (추적 및 반격 루프)
* 몬스터가 정적인 더미가 아닌, 서버 내부의 500ms(0.5초) 백그라운드 틱(`ChannelUpdateLoopAsync`) 위에서 자율적으로 판단합니다.
* **Aggressive (선공)**: 플레이어가 시야(15.0f 반경) 안에 들어오면 즉시 타겟을 변경하여 플레이어 위치를 향해 스스로 좌표를 좁히며 다가옵니다(추적).
* **Retaliate (반격)**: 선공이 아닌 일반 몬스터라도 외부 타격을 받으면 데미지를 가한 공격자를 타겟(TargetPlayerId)으로 설정하고 쫓아옵니다.
* 사거리 내에 도달하면 주기적(1.5초)으로 플레이어에게 피해를 입히는 난투형 AI가 구현되어 있습니다.
